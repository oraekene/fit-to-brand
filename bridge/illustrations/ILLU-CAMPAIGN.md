# Illustration 3 — Campaign expansion only (fictional SunJar, amber system live)

Orchestration: `bridge/CAMPAIGN-EXPANSION-ORCHESTRATION.md`. Premise: the amber Anchor
is approved, Brand Lock passes, GRP-01 flight is scaling — marketing now wants more
assets: a harmattan-season variant, a 9:16 stall vertical, a Yoruba-language market-day
edition, and a rooftop-install web cut. **Zero new strategy, zero new identity.**
**All figures are illustrative, not market data.** Miniature artifacts in
`data-campaign/`; quoted H1 lines are real outputs (`hook-campaign-brand.txt`,
`hook-campaign-m.txt`).

1. `ANCHOR STATUS: APPROVED` with locked rules + prohibitions in checkpoint — shown.

## Phase 1 — Thread plan

`STATUS` review confirms Anchor version, pack ref currency (no SKU change), brief
validity. Thread table (`data-campaign/bridge/THREADS.csv` plus M rows in
`M_PREDICTIONS.csv`):

- GRP-01 × harmattan morning 1:1 (new scene family → test asset required) — PRED-C1.
- GRP-02 × stall canopy 9:16 vertical (new format class → recompose + safe-area check;
  test asset required) — PRED-C2.

  PRED-C2's thread family after its own audit.
- GRP-03 × rooftop install 16:9 web (proven direction, repeat order) — PRED-C3.

Sequencing: proven rooftop first (funds learning), then vertical, then harmattan;
one new scene family at a time.

## Phase 2 — Per-thread execution (two loops shown in full)

**Rooftop repeat (fast path).** Roles confirmed (rooftop moment already locked) →
Generation Plan approved (profile + cost + fonts + prohibitions + 3 outputs 16:9 +
text fallback) → no new test asset needed (same family, same architecture) → audit
**APPROVED** → scale 3 SKU cuts → organized by scene/SKU/format, cost actuals logged
to M2. Four steps, no drama — the common case, shown so the slow case reads correctly.

**Harmattan variant (slow path).** New scene family → fresh test asset → audit
**CORRECTION REQUIRED** (major: haze washed the amber rail below contrast spec;
PRESERVE: composition, headline tier, pack face) → correct exactly that (rail grade
lifted, nothing else touched) → re-audit **APPROVED** → scale. The audit-then-correct
loop is the mechanism that keeps 40 assets feeling like one brand; skipping it is how
drift compounds silently.

## Phase 5 — M1–M4 per flight (verdicts that show the diagnostic split)

- PRED-C1 harmattan: trial requests 1.1/100 (leading ✓), PAYG conversion at plan
  (lagging ✓) → **SCALE**; approved as second GRP-01 scene family.
- PRED-C2 vertical: swipe-through 3.4 (leading ✓✓) but trial starts flat (lagging ✗)
  → **FIX-LOGIC**: expression works, bet untested at this format — reopen GRP-02
  placement/CTA (is the CTA thumb-reachable? is the hook in the first frame?), do
  NOT redesign the kit. The mirror error (redesigning on a logic failure) is named in
  the decision so the next reader doesn't make it.
- Yoruba edition probe: confusion-with-P-0003 12% (over the 10% trip) →

- Kill latency tracked: vertical CTA fix ships in 6 days from trip; loop's own KPI
  logged.

M4 addresses: S5B GRP-02 brief gains a format-placement note; S4 findings + NOT-fit
